# 网页端网盘上传设计（第一期）

日期：2026-10-18  
状态：已确认  
范围：`pan-tools` 网页端转存页；百度 / 夸克 / 迅雷

## 目标

在转存（文件浏览）页支持将本地**文件或文件夹**上传到网盘，交互接近百度网盘的基础上做精简版进度反馈。

## 决策摘要

| 项 | 选择 |
|----|------|
| 端 | 网页端 `pan-tools` |
| 网盘 | 百度 + 夸克 + 迅雷 |
| 入口 | 工具栏「上传」→ 当前目录；文件夹行「上传到此」→ 该文件夹 |
| 传输路径 | 浏览器 → 后端 → 各盘 adapter（中转，非浏览器直传 CDN） |
| 进度 | 右下角浮层：进度 + 取消；完成后刷新列表 |
| 不做 | 上传任务中心、暂停/继续、拖拽上传、秒传专项 UI |

## 1. 交互

### 入口

- **工具栏**：按钮「上传」，可选「上传文件」或「上传文件夹」（`input[webkitdirectory]`）。
- **操作列**：仅文件夹行显示「上传到此」，同样可选文件或文件夹。
- **目标目录**：工具栏 = 当前浏览路径；操作列 = 该行文件夹路径。
- 未选账号时禁用上传并提示。

### 流程

1. 用户选择本地文件（可多选）或文件夹。
2. 前端创建上传任务并开始上传；右下角显示名称、目标路径、进度、取消。
3. 成功后刷新当前目录列表；失败展示简短错误文案。
4. 文件夹上传保持相对路径结构（在目标目录下重建子目录）。

### 第一期不做

- 「上传中 / 已完成」独立列表页
- 暂停 / 继续
- 拖拽到页面上传
- 秒传结果的专门展示（底层仍可做秒传，但不做专项 UI）

## 2. 后端任务与 API

### 模型 `upload_tasks`

对齐现有 `download_tasks`：

| 字段 | 说明 |
|------|------|
| `user_id` / `account_id` | 用户与网盘账号 |
| `dest_path` | 网盘目标目录 |
| `name` | 展示名（单文件名，或「文件夹（n 个文件）」） |
| `status` | `running` / `done` / `failed` / `cancelled` |
| `bytes_done` / `bytes_total` | 字节进度 |
| `files_done` / `files_total` | 文件个数进度 |
| `current_name` | 当前正在传的文件名 |
| `error` | 失败原因 |
| `created_at` / `updated_at` | 时间戳 |

执行方式与目录下载相同：**API 进程内后台线程**，不进入 transfer/share/sync 的 `Job` worker。

### HTTP API

- `POST /api/accounts/{account_id}/files/upload`  
  - `multipart/form-data`  
  - `dest`：目标目录路径  
  - 一个或多个文件字段；每个文件可带相对路径（浏览器 `webkitRelativePath` 或表单字段 `relative_path`），用于还原文件夹结构  
  - 响应：创建后的 `UploadTask`（含 id，供轮询）

- `GET /api/uploads`：当前用户最近上传任务（前端轮询进度）

- `POST /api/uploads/{task_id}/cancel`：取消进行中的任务

### Adapter 约定

各网盘 adapter 实现：

- `ensure_dir(cookie, path)`：确保目标子目录存在（按路径逐级创建）
- `upload_file(cookie, dest_dir, filename, stream, size, progress_cb)`：上传单个文件；分片/合并/秒传由各实现内部处理

统一由 `services/uploads.py`（名称可微调）编排：写临时文件 → 调 adapter → 更新 `upload_tasks` → 清理临时文件 → 响应取消。

### 限制

- 单文件或单次任务总大小默认上限 **4GB**（配置项可调）
- **同一账号串行**上传，降低限流风险；不同账号可并行
- 临时文件用完即删
- 进程启动时将残留 `running` 标为 `failed`（与下载 `interrupt_orphans` 同类）

## 3. 三家适配与风险

### 适配

| 网盘 | 实现要点 |
|------|----------|
| 百度 | 既有 cookie 会话；预创建 + 分片 + 合并（PCS/网盘上传链路） |
| 夸克 | 按其 drive 上传协议；父目录使用现有 list 的 id/路径体系 |
| 迅雷 | 按其 drive API；token 刷新复用现有逻辑 |

第一期目标：文件/文件夹可传、有进度、可取消。不承诺极限速度或完整秒传产品化展示。

### 风险与缓解

| 风险 | 缓解 |
|------|------|
| 大文件占服务器带宽与磁盘 | 大小上限、临时目录、传完删除、同账号串行 |
| 网盘限流 / 风控 | 有限次重试；失败写入 `error` |
| 文件夹选择浏览器兼容性 | 以 Chromium 为主；不支持时仅提供「上传文件」 |
| 三家协议变更 | HTTP mock 单测；一家失败不影响其它 |

## 4. 验收标准

1. 百度 / 夸克 / 迅雷账号下，工具栏可上传文件到当前目录。  
2. 可上传文件夹并保持相对路径结构。  
3. 文件夹行「上传到此」上传到对应目录。  
4. 右下角显示进度且可取消；完成后目录列表刷新。  
5. 超限、登录失效等有明确错误提示。
