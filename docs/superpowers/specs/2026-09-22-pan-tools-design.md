# 网盘拉新工具设计

日期：2026-09-22

第一版是一个多用户 Web 后台。运营者手动开通付费会员。用户粘贴自己的百度 Cookie，完成批量转存、批量分享导出，以及分享数据查询。夸克和迅雷只保留适配器接口，这一版不实现。

## 目标

运营者把软件部署在自己的服务器上，把账号卖给做百度网盘拉新的用户。用户不直接调用百度。核对登录和列目录由 API 进程完成，转存、分享和同步由 Worker 完成。

第一版做完的标志：

- 用户可以注册、登录。
- 管理员可以把用户设为付费，并填写到期时间。
- 用户可以绑定百度账号，按等级批量转存。
- 付费用户可以对一个目录下的文件和子目录批量创建分享，并导出 CSV。
- 付费用户可以查看分享总量、时间范围内的新增数据，以及两种转存排行榜。

## 非目标

- 不接微信、支付宝或任何在线支付。
- 不实现夸克、迅雷的真实请求。
- 不递归分享子目录内部的文件。
- 不自动重命名已存在的同名文件。
- 不统计本系统第一次同步之前的每日增量。
- 不查询别人分享链接的浏览、转存、下载数，只统计当前绑定账号自己的分享记录。

## 结构

```text
浏览器
  └─ 前端（Vite + React + TypeScript + Ant Design）
        │ 只调用自己的 API
        ▼
     API（FastAPI）
        │ 注册登录、会员、网盘账号、创建任务、导出、查询统计
        ▼
     PostgreSQL
        ▲
        │ 领取任务并回写结果
     Worker（同一套 Python 代码，单独进程）
        └─ 网盘适配器
              ├─ 百度（第一版实现）
              ├─ 夸克（调用时返回「暂未开放」）
              └─ 迅雷（调用时返回「暂未开放」）
```

仓库分成 `backend/` 和 `frontend/`。Docker Compose 运行四个容器：前端静态文件、API、Worker、PostgreSQL。

各部分的边界：

| 部分 | 职责 | 依赖 |
|---|---|---|
| 前端 | 页面和表单 | 只依赖 API |
| API | 鉴权、会员校验、任务入队、统计查询、CSV 导出 | 数据库 |
| Worker | 执行转存、分享、分享列表同步和快照 | 数据库、网盘适配器 |
| 网盘适配器 | 对百度发请求，向上提供统一动作 | 百度 HTTP，不访问数据库 |

业务代码只调用这些动作：核对登录、列目录、转存分享、创建分享、分页读取分享记录。API 进程只调用前两个只读动作，用于绑定账号和展示目录。转存、创建分享和同步只由 Worker 调用适配器。Worker 一次只执行一个任务，任务内的条目按顺序执行，降低被限流的概率。

## 账号和会员

用户使用邮箱和密码注册。密码用 bcrypt 存储。登录成功后签发 JWT，放在 `HttpOnly` Cookie 中。生产环境启用 `Secure`。

角色有两种：`user` 和 `admin`。等级有两种：`free` 和 `paid`。付费用户有到期时间，到期后按免费用户处理。

启动时如果还不存在管理员，用环境变量 `ADMIN_EMAIL` 和 `ADMIN_PASSWORD` 创建第一个管理员。

管理员可以查看用户列表，把某个用户设为免费或付费，并修改到期时间。管理员自己使用转存、分享和数据查询时不计入额度，也不受免费限制。

| | 免费 | 付费 |
|---|---|---|
| 可绑定百度账号 | 1 个 | 5 个 |
| 夸克 / 迅雷 | 不可绑定 | 第一版不可绑定 |
| 每日转存 | 100 条 | 无上限 |
| 批量分享并导出 | 关闭 | 无上限 |
| 数据查询 | 关闭 | 开放 |

「每日」按上海时区的自然日计算。免费用户提交转存时，若本次条数加上今日已入队的转存条数超过 100，整批拒绝，不创建任务，已用条数不变，并返回今日剩余条数。任务一旦创建，本次条数立即计入用量，不论这些条目最终成功还是失败。付费用户的转存和分享仍然写入用量，供管理后台查看，但不因条数拒绝。

被拒绝的操作直接返回错误，不创建任务：

- 超过免费转存额度。
- 免费用户使用分享、导出或数据查询。
- 绑定夸克或迅雷。
- 分享时没有勾选任何文件或目录。
- 转存目标目录在该百度账号中不存在。

## 数据

### users

邮箱、密码哈希、角色、等级、付费到期时间、创建时间。

### pan_accounts

所属用户、网盘类型（`baidu` / `quark` / `xunlei`）、网盘昵称、加密后的 Cookie、状态（`valid` / `expired`）、创建和更新时间。

Cookie 使用 Fernet 加密，密钥来自环境变量 `COOKIE_FERNET_KEY`。接口响应和日志都不包含 Cookie 原文。前端只显示昵称和状态。

### jobs / job_items

一次批量操作是一条 `job`，类型为 `transfer`、`share` 或 `sync`。转存和分享中，每条链接或每个分享对象是一条 `job_item`。`sync` 任务不拆条目，失败原因记在任务上。

任务状态：`pending`、`running`、`succeeded`、`partial`、`failed`。

条目状态：`pending`、`running`、`succeeded`、`failed`。条目保存输入、失败原因、结果和已尝试次数。

### share_links

同步该百度账号分享记录中的全部分享，不只是本系统创建的。字段包括：百度分享 ID、名称、路径、分享链接、提取码、创建时间、是否过期、最近一次累计浏览数、累计转存数、累计下载数。提取码只有本系统创建的分享才有；从百度同步来的历史分享，提取码为空。

用户在百度删除、因而分享记录里已经不存在的链接，标记为 `removed`，不计入总量和排行，已有快照保留。已过期但仍在百度分享记录里的链接保持有效。同步成功后按百度分享 ID 更新已有记录；这次列表中没有的旧记录标记为 `removed`，不整表删除。

### share_stat_snapshots

每条分享在某个时刻的累计浏览、转存、下载。每天 0:05（上海时区）为所有状态有效的付费账号写一份快照。用户在数据页点击刷新并同步成功后，再写一份。

### daily_usage

按用户和上海时区日期记录转存条数、分享条数。

## 绑定百度

用户把浏览器中的百度 Cookie 贴到表单。API 进程调用百度适配器核对登录。核对成功后加密保存，并写入网盘昵称，状态为 `valid`。核对失败则不保存，页面提示重新登录后再贴。

更新 Cookie 时走同一套核对。一个用户的有效百度账号数量不能超过其等级上限。

## 批量转存

用户选择一个状态为 `valid` 的百度账号，粘贴多行分享链接，再选择自己网盘里的一个目录。目录列表只展示当前层。

每条链接的全部内容转入该目录。支持这三种写法，提取码可省略：

- `https://pan.baidu.com/s/1xxxx?pwd=abcd`
- `https://pan.baidu.com/s/1xxxx 提取码: abcd`
- `https://pan.baidu.com/s/1xxxx abcd`

某一条失败不影响其余条目。全部成功时任务为 `succeeded`，有成功也有失败时为 `partial`，全部失败时为 `failed`。

单条失败的原因包括：链接无法解析、链接无效、提取码错误、目标目录已有同名文件。第一版不自动改名。

百度返回限流时，该条按 2 秒、8 秒、20 秒的间隔重试。限流重试和 Worker 中断后的重新入队共用同一个尝试计数，最多 3 次。第 3 次仍失败，该条记为失败，任务继续。

执行中如果 Cookie 失效，账号状态改为 `expired`，尚未执行的条目记为「登录已失效，请重新粘贴 Cookie」，不再请求百度。

Worker 重启后，处于 `running` 且超过 15 分钟没有更新的条目重新进入 `pending`。尝试次数同样受最多 3 次限制。

## 批量分享和导出

仅付费用户和管理员可用。用户选择百度账号和一个目录，系统列出这一层的文件和子目录，不进入子目录内部。用户勾选若干项，每一项创建一条分享。

默认永久有效，每条分享使用各自随机的 4 位提取码。用户可以改成所有分享共用一个提取码，或把有效期改成 1 天、7 天。

创建成功的分享写入 `share_links`。用户可以把这一批结果导出为 CSV，列为：名称、路径、分享链接、提取码、创建时间。文件使用带 BOM 的 UTF-8。

## 数据查询

仅付费用户和管理员可用。页面先选择一个百度账号。时间快捷项为当天、最近一周、最近一个月，时区为上海。

时间范围的定义：

- 当天：当天 00:00 至当前时刻。
- 最近一周：含今天在内、向前连续 7 天，从起始日 00:00 至当前时刻。
- 最近一个月：含今天在内、向前连续 30 天，从起始日 00:00 至当前时刻。

这个时间选择作用于汇总，以及排行榜的时间范围模式。历史模式忽略它。

### 分享总量

当前同步下来的有效分享条数，包含本系统启用前创建的分享，也包含已过期但仍在百度分享记录中的分享。

### 所选时间范围内的汇总

- 新增分享：分享创建时间落在范围内的条数。这个数来自分享记录上的创建时间，不依赖快照。
- 转存、浏览、下载：范围内的新增量，按下面的规则对每条分享计算后再求和。

增量的起点和结束值：

1. 若存在不晚于范围开始时刻的快照，增量等于最新累计值减去这份快照的累计值。
2. 若没有这份快照，但范围内至少有两份快照，增量等于最新一份减去最早一份。页面标明「本段从 {最早快照时间} 起算」。这样用户刚开始使用时，最近一周和最近一个月不会整段空白。
3. 若从未同步，或范围内只有一份快照，该指标显示「暂无」，不用 0 代替。
4. 百度没有返回某个累计字段时，该字段保存为空，对应增量显示「暂无」。

页面同时写明该账号第一份成功快照的日期。

### 转存排行榜

每行展示分享链接、转存量、浏览量、下载量。默认每页 20 条。转存量相同的，按分享创建时间从新到旧排列。

- 历史模式：不看时间选择。按累计转存从高到低排列全部有效分享。浏览量和下载量使用累计值。
- 时间范围模式：按当前时间范围的转存增量从高到低排列。浏览量和下载量使用同一范围、同一套减法规则。无法计算的数字显示「暂无」，不用 0 参加排序；这些行排在有转存增量的行后面。

### 同步

用户点击刷新，或每天 0:05 的定时任务，会为每个状态有效的付费账号创建一条 `sync` 任务。Worker 分页拉取全部分享记录。全部分页成功后，才按上一节的规则更新本地分享并写入快照。任一页失败则不修改本地分享，不写快照，页面向用户显示这次同步失败。

定时快照按账号隔离。一个账号 Cookie 失效时，把该账号标为 `expired` 并跳过，不影响其他账号。

## 出错处理汇总

| 情况 | 处理 |
|---|---|
| 额度、权限、空选择、目标目录不存在 | 提交阶段拒绝，不创建任务 |
| 单条链接或单条分享失败 | 记下原因，继续其余条目 |
| 百度限流 | 最多 3 次，间隔 2 秒、8 秒、20 秒 |
| Cookie 失效 | 账号标为已失效，停止该账号后续请求 |
| Worker 中断 | 超过 15 分钟的 `running` 条目重新排队，最多 3 次 |
| 分享列表分页中断 | 保留旧列表，不写快照 |
| 快照不足以相减，或百度未返回某个计数 | 显示「暂无」，不用 0 代替 |

## 测试

测试不访问真实百度。适配器用录好的 HTTP 响应夹具。

会员和额度：

- 免费用户每天第 101 条转存被拒绝，已用条数不变。
- 付费用户的转存和分享不因条数被拒绝。
- 免费用户调用分享、导出、数据查询被拒绝。
- 付费到期后按免费用户处理。
- 夸克、迅雷绑定被拒绝。

转存和分享：

- 三种链接写法都能解析出地址和提取码。
- 提取码错误或链接无效时只失败该条。
- 部分成功时任务状态为 `partial`。
- Cookie 失效后，账号状态为 `expired`，未执行条目不再产生百度请求。
- CSV 列和编码符合上面的导出约定。

数据查询：

- 分享列表分页中途失败时，保留旧列表且不写快照。
- 有范围开始前的快照时，增量等于最新累计值减去该快照。
- 只有范围内的快照、且至少有两份时，增量从最早一份起算，并带有起算时间。
- 不足以相减时结果为「暂无」。
- 新增分享按创建时间落入三个时间范围计数。
- 历史排行按累计转存排序；时间范围排行按该范围的转存增量排序，浏览和下载使用同一口径。

接口：

- 未登录不能访问业务接口。
- 普通用户不能访问管理接口，也不能修改他人等级。
- 接口响应和日志中不出现 Cookie 原文。

## 页面

- `/login`、`/register`：登录和注册。
- `/accounts`：绑定百度、查看状态、更新 Cookie。
- `/transfer`：批量转存，并进入任务详情。
- `/share`：批量分享，以及导出这一批 CSV。
- `/stats`：选择账号和时间，查看总量、汇总和两种排行。
- `/jobs/:id`：任务进度和每条的失败原因。
- `/admin/users`：管理员修改等级和到期时间。

## 实现顺序

实现时按这个顺序交付，每一步都可以单独验证：

1. 注册登录、管理员、会员等级。
2. 百度账号绑定和 Cookie 加密。
3. 批量转存。
4. 批量分享和 CSV 导出。
5. 分享同步、快照和数据查询。
